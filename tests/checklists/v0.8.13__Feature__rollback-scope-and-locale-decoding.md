# Human Test Checklist: Rollback Scope and Locale Decoding

**Target version:** v0.8.13
**Ships with commit:** TBD (pre-commit at time of writing)
**Companion automated tests:** 249 tests in `tests/unit/` — `test_rollback_scope.py` (25) is the one specific to this release

## What this is

v0.8.13 fixes two day-one bugs reported from a German Windows install ([#36](https://github.com/DazzleML/comfyui-triton-and-sageattention-installer/issues/36)), plus a third found while verifying them. All three are about the installer doing something destructive that the user did not ask for:

1. Command output was decoded with the machine's ANSI codepage, so one umlaut from `nvcc`/`cl`/`nmake` crashed the run on any non-English Windows.
2. That crash then triggered a "cleanup" that uninstalled a **hardcoded** package list — including PyTorch — whether or not the run had installed any of it.
3. The CPU→CUDA switch deliberately uninstalls PyTorch before reinstalling; if the reinstall failed, nothing put it back.

**The property under test throughout:** *the installer may undo its own work; it may never undo yours.* Every step below is a variation on "did something get removed that this run did not install?"

Automated tests cover the decision — *what would be uninstalled* — by mocking `pip_uninstall`. They cannot cover the interactive prompt, real pip failures mid-operation, or non-English console output. That is what this document is for.

## Prerequisites

1. **Windows**, NVIDIA GPU, Python 3.10–3.13.
2. **MSVC Build Tools** for Section 3 only (to compile the German shims). Skip that section without it.
3. **A scratch ComfyUI you do not care about.** Several steps deliberately break installs.
4. Do **not** run this against your real ComfyUI. Nothing here needs it.

```cmd
set CTS=%TEMP%\cts_0813
```

## High-Value Verification (~10 minutes)

### HV.1 — A failed install removes nothing when it installed nothing

The reported bug, in one command.

- [ ] **Steps** — force a failure by pointing pip at a dead index:

  **cmd.exe**
  ```cmd
  set PIP_INDEX_URL=http://127.0.0.1:9/nope
  set PIP_RETRIES=0
  set PIP_TIMEOUT=3
  python comfyui_triton_sageattention.py --install --non-interactive --base-path "%CTS%\comfy" --python "%CTS%\emptyvenv\Scripts\python.exe"
  set PIP_INDEX_URL=
  ```

  **PowerShell**
  ```powershell
  $env:PIP_INDEX_URL="http://127.0.0.1:9/nope"; $env:PIP_RETRIES="0"; $env:PIP_TIMEOUT="3"
  python comfyui_triton_sageattention.py --install --non-interactive --base-path "$env:CTS\comfy" --python "$env:CTS\emptyvenv\Scripts\python.exe"
  Remove-Item Env:\PIP_INDEX_URL
  ```

  **POSIX**
  ```bash
  PIP_INDEX_URL=http://127.0.0.1:9/nope PIP_RETRIES=0 PIP_TIMEOUT=3 \
    python comfyui_triton_sageattention.py --install --non-interactive \
    --base-path "$CTS/comfy" --python "$CTS/emptyvenv/Scripts/python.exe"
  ```
- [ ] **Expected:** `Installation failed: ...` then **`Nothing to roll back - this run installed no packages.`**
- [ ] **Must NOT see:** `Uninstalling Triton dependency...`, or any `Skipping <pkg> as it is not installed` lines. Those mean the old hardcoded teardown ran.
- [ ] **Why this matters:** on a machine that *does* have PyTorch, those `Skipping` lines read `Successfully uninstalled torch` instead. That is the reported incident.

### HV.2 — `--cleanup` asks before removing PyTorch

- [ ] **Steps:** `python comfyui_triton_sageattention.py --cleanup --base-path "<CTS>/comfy"`
- [ ] **Expected:** the package list is printed, a warning that this includes PyTorch, then a `(y/N)` prompt.
- [ ] **Answer `n`.** Expect `Cleanup cancelled - no packages removed.` and no uninstall.
- [ ] **Run again and answer `no`** (the word). Must also cancel — `n`-only matching was a real bug in v0.8.12.
- [ ] **Run again and press Ctrl-C** at the prompt. Must exit cleanly, no traceback.
- [ ] **Why this matters:** this removes PyTorch. It is the most destructive thing the tool can do on request.

### HV.3 — `--cleanup --non-interactive` declines rather than assuming consent

- [ ] **Steps:** `python comfyui_triton_sageattention.py --cleanup --non-interactive --base-path "<CTS>/comfy"`
- [ ] **Expected:** a message that it is skipping removal, and **no** uninstall.
- [ ] **Why this matters:** a scripted teardown that does not happen can be re-run; one that does cannot be undone.

### HV.4 — A failed CPU→CUDA upgrade puts PyTorch back

The fix that is hardest to reach and most consequential when it fires.

- [ ] **Steps:**
  1. Give the scratch venv a real CPU-only PyTorch:
     ```
     "<CTS>/emptyvenv/Scripts/python.exe" -m pip install --index-url https://download.pytorch.org/whl/cpu "torch==2.5.1+cpu"
     ```
  2. Confirm: `"<CTS>/emptyvenv/Scripts/python.exe" -c "import torch; print(torch.__version__)"` → `2.5.1+cpu`
  3. Run `--install` with the dead-index environment variables from HV.1, so the CUDA install fails **after** the CPU torch is removed.
- [ ] **Expected:** `Restoring packages this run removed: torch==2.5.1+cpu` then `Restored.`
- [ ] **Check:** step 2's command again → still `2.5.1+cpu`.
- [ ] **If the restore itself fails** (it may, with pip pointed at a dead index): the output must print the exact `pip install ... torch==2.5.1+cpu` command **and** mention `--backup-restore`. Being left without PyTorch is acceptable only if the way back is on screen.
- [ ] **Why this matters:** this is the only place the installer removes working packages on purpose.

## Section 1: Rollback scope details (~5 min)

### 1.1 A partial install rolls back only its own part

- [ ] **Steps:** Let a real install get far enough to install PyTorch, then interrupt it with Ctrl-C during the Triton or SageAttention step.
- [ ] **Expected:** rollback lists only what actually got installed.
- [ ] **Check:** nothing that was in the environment beforehand is gone.

### 1.2 Rollback survives a failing uninstall

- [ ] **Steps:** Trigger a failure while a package file is locked (e.g. keep a Python REPL open with `import torch`).
- [ ] **Expected:** a warning that some packages could not be rolled back. No traceback, no hang.

## Section 2: `--cleanup` (~5 min)

### 2.1 Confirmed cleanup does remove the stack

- [ ] **Steps:** On a scratch environment with packages installed, run `--cleanup` and answer `y`.
- [ ] **Expected:** the listed packages are removed. This is correct — the user asked.
- [ ] **Check:** the venv itself still exists unless you separately confirmed its removal.

### 2.2 The venv removal prompt is separate

- [ ] **Expected:** removing packages and removing the virtual environment are two distinct questions. Declining one must not imply the other.

## Section 3: Non-English Windows (~10 min, needs MSVC)

You do not need a German machine — the harness builds tools that behave like one.

### 3.1 Build the German shims

- [ ] **Steps:** `python tests/one-offs/make_german_locale_shims.py --out "<CTS>\shims"`
- [ ] **Expected:** `nvcc.exe` and `nmake.exe` built, each reporting `0x81 present`.

### 3.2 The installer survives German tool output

- [ ] **Steps:** Prepend `<CTS>\shims` to `PATH`, then run `--install --dryrun` against the **torch-less** venv.

  **cmd.exe**: `set PATH=%CTS%\shims;%PATH%`
  **PowerShell**: `$env:PATH = "$env:CTS\shims;$env:PATH"`
  **POSIX**: `export PATH="$CTS/shims:$PATH"`
- [ ] **Expected:** a normal plan. CUDA is detected as `13.2` (parsed out of the German text).
- [ ] **Must NOT see:** `UnicodeDecodeError`, `charmap`, or `NoneType`.

### 3.3 The reported crash path specifically

- [ ] **Steps:** Rename `nvcc.exe` to `nvcc.exe.off` in the shim directory so the real `nvcc` is used and only `nmake` is German. Run a real `--install`.
- [ ] **Expected:** `Visual Studio Build Tools already installed`, then the install proceeds.
- [ ] **Must NOT see:** `argument of type 'NoneType' is not iterable` followed by a cleanup.
- [ ] **Why the rename:** `nvcc` is probed *before* `install()`'s try block, so shimming it produces a different (also fixed) crash. The reported one is in the `nmake` build-tools check, inside the try — which is why cleanup ran on the reporter's machine.

## What the automated tests DO cover

| Area | File | Count |
|---|---|---|
| Rollback scope, `--cleanup` consent, index inference, restore-on-failure | `tests/unit/test_rollback_scope.py` | 25 |
| Everything else (plan/execute, wheels, backup, prompts, rendering) | rest of `tests/unit/` | 224 |
| **Total** | | **249** |

Destructive paths are tested by mocking `pip_uninstall` and asserting the **argument list** — what *would* be removed. That is exactly the property that was wrong, and it is safe to assert without uninstalling anything.

## What the automated tests DON'T cover

- **The interactive prompt.** Rendering, Ctrl-C, and whether "no" reads naturally.
- **Real pip failures mid-operation** — locked files, dropped connections, partial installs.
- **Real console output from localized tools.** Section 3 approximates it; a genuine German Windows may produce output we have not seen.
- **Whether the restore actually restores a working environment** rather than just reporting success.
- **Timing** — how long a user stares at a failed install before the rollback message appears.

## Reporting issues found

1. Note the section number and the exact command.
2. Include `python comfyui_triton_sageattention.py --version` and `--show-installed`.
3. For locale issues: include `chcp` output and your Windows display language.
4. Attach `comfyui_install.log`.
