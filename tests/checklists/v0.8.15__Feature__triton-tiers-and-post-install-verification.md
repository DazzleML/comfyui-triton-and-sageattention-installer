# Human Test Checklist: Triton constraint tiers + post-install verification

**Target version:** v0.8.15
**Ships with commit:** TBD (v0.8.15: Fix phantom Triton upgrade; add post-install verification)
**Companion automated tests:** 317 passing + 2 xfail — new in this release: tests/unit/test_post_install_verify.py (19), execution-dispatch tests in tests/unit/test_plan_exec_agreement.py (5), tier/probe/filter tests in tests/unit/test_installplan_matrix.py (28). Mutation sweep: tests/mutation/v0.8.15__sweep__verify-install-outcome.md (12/12 killed).

## What this is

Hand-runnable verification for the v0.8.15 release, which fixes the "phantom Triton upgrade" (dryrun claimed `UPGRADE 3.6.0.post26 -> 3.7.1.post27` forever; the real run skipped forever) and adds a report-only post-install verifier that compares the plan's claims against the actual environment after every install. Run it on a Windows machine with a real or throwaway ComfyUI directory. The most valuable pass is on a machine with PyTorch 2.10.x + Triton 3.6.x installed — the exact configuration the original bug hit.

## Prerequisites

1. Windows 10/11, Python 3.10+ on PATH, this repo checked out at the v0.8.15 commit.
2. A **throwaway** ComfyUI-shaped directory for the destructive/fresh tests (HV.4, Section 2). Create it:

   **cmd.exe**:
   ```cmd
   mkdir %TEMP%\fake_comfyui\custom_nodes %TEMP%\fake_comfyui\models
   type nul > %TEMP%\fake_comfyui\main.py
   ```
   **PowerShell**:
   ```powershell
   New-Item -ItemType Directory -Force "$env:TEMP\fake_comfyui\custom_nodes","$env:TEMP\fake_comfyui\models" | Out-Null
   if (-not (Test-Path "$env:TEMP\fake_comfyui\main.py")) { New-Item -ItemType File "$env:TEMP\fake_comfyui\main.py" | Out-Null }
   ```
   **POSIX**:
   ```bash
   mkdir -p /tmp/fake_comfyui/custom_nodes /tmp/fake_comfyui/models && touch /tmp/fake_comfyui/main.py
   ```
3. For HV.1–HV.3 you want a REAL environment with torch 2.10.x+cu13x and triton-windows 3.6.0.postN installed (read-only checks — the plan should be all-KEEP, so nothing is modified; still, `--backup` first if the environment matters to you).
4. Reset between sections: delete `%TEMP%\fake_comfyui\venv` to return the fake dir to fresh state.

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these five. All commands below are `python comfyui_triton_sageattention.py ...` from a ComfyUI directory (or with the script's absolute path).

### HV.1 — dryrun and upgrade agree about Triton (the fixed bug)

Validates: `install_triton()` full dispatch + one-minor tier fix.

- [ ] **Steps** (real env, torch 2.10 + triton 3.6.0.post26):
  1. `python comfyui_triton_sageattention.py --upgrade --dryrun`
  2. `python comfyui_triton_sageattention.py --upgrade`
- [ ] **Expected:** BOTH show `Triton [KEEP] 3.6.0.post26`. The dryrun must NOT propose 3.7.1.x (that Triton pairs with torch 2.12). The real run must not say anything the dryrun didn't claim.
- [ ] **Why this matters:** this exact disagreement shipped in v0.8.6–v0.8.14 and is the reason this release exists.
- [x] *Verified live 2026-08-10 on the maintainer's RTX 5090 box (torch 2.10.0+cu130, triton 3.6.0.post26): both KEEP, byte-consistent.*

### HV.2 — the post-install verification block appears and is truthful

Validates: `_verify_install_outcome()` wiring and output rendering.

- [ ] **Steps:** run `--upgrade` (or `--install`) to completion on any environment.
- [ ] **Expected:** before the final status line, a block:
  ```
  ----------------------------------------------------------------------
  Post-install verification (plan vs. environment)
  ----------------------------------------------------------------------
    [OK]        PyTorch        KEEP      ... (unchanged)
    [OK]        Triton         ...
    [OK]        SageAttention  ...
    [OK]        build tools    pip/setuptools unchanged (not authorized)

    Result: N check(s) passed, 0 deviation(s).
  ```
  followed by `Success!`. Every `[OK]` row's version must match `--show-installed`. ASCII only — no mojibake on cp437/cp1252 consoles.
- [ ] **Why this matters:** this is the new self-check; if it lies or crashes the install, it is worse than absent.
- [x] *Verified live 2026-08-10: 4 checks passed, 0 deviations, ~2s added.*

### HV.3 — a no-change plan no longer touches setuptools

Validates: the phantom-upgrade collateral is gone.

- [ ] **Steps:** on an up-to-date environment, run `--upgrade` and note setuptools version before/after:
  - **cmd.exe**: `venv\Scripts\python.exe -m pip show setuptools | findstr Version`
  - **PowerShell**: `& venv\Scripts\python.exe -m pip show setuptools | Select-String Version`
  - **POSIX**: `venv/bin/python -m pip show setuptools | grep Version`
- [ ] **Expected:** output contains `Build tools: pip/setuptools unchanged (nothing to install)`; setuptools version identical before and after.
- [ ] **Why this matters:** on 2026-08-10 a phantom UPGRADE authorized a real setuptools 83->84 replacement the preview never mentioned.
- [x] *Verified live 2026-08-10.*

### HV.4 — custom-node preview shows exactly two rows

Validates: the vestigial duplicate rows are gone.

- [ ] **Steps:** from the fake ComfyUI dir: `python <path>\comfyui_triton_sageattention.py --install --dryrun --with-custom-nodes --non-interactive`
- [ ] **Expected:** Proposed Changes lists `ComfyUI-VideoHelperSuite` and `DazzleNodes` ONCE each — not four node rows, and no bare `VideoHelperSuite` row.
- [ ] **Why this matters:** duplicated rows were live proof of the dual-renderer problem; their absence pins the plan as the only row source.

### HV.5 — probe runs constrained with --pre

Validates: within-tier upgrades stay reachable after the tier tightening.

- [ ] **Steps:** run `--upgrade --dryrun` and read the INFO log lines (console or `comfyui_install.log`).
- [ ] **Expected:** the probe line reads `pip install --dry-run --upgrade --pre triton-windows>=3.6,<3.7` (tier matching your torch) — NOT a bare `--upgrade triton-windows`.
- [ ] **Why this matters:** unconstrained, pip only reports the global latest; the tightened filter would reject it and legitimate 3.6.0.postN updates would silently freeze.
- [x] *Verified live 2026-08-10.*

## Section 1: Tier behavior (read-only, ~5 min)

### 1.1 Tier table spot-checks

- [ ] **Steps** (same across all shells, one-liner):
  ```
  python -c "import comfyui_triton_sageattention as m; i=object.__new__(m.ComfyUIInstaller); print(i._get_triton_version_constraint('2.10.0'), i._get_triton_version_constraint('2.12.0'), i._get_triton_version_constraint('2.9.1'))"
  ```
- [ ] **Expected:** `>=3.6,<3.7 >=3.7,<3.8 >=3.5,<3.6`
- [ ] **Check:** `docs/supported_wheels.md` table matches these values.

### 1.2 --show-installed still reports compatibility correctly

- [ ] **Steps:** `python comfyui_triton_sageattention.py --show-installed` on the real env.
- [ ] **Expected:** `Triton/PyTorch: [OK] Compatible (Triton 3.6.x with PyTorch 2.10)` (or your pairing). No FIX suggestion for a working torch 2.12 + triton 3.6 combination — the FIX trigger requires confirmed incompatibility, and that pairing is merely unknown.

## Section 2: Fresh-install path (destructive to the fake dir only, ~10 min)

### 2.1 Fresh dryrun makes deferred claims, not false ones

- [ ] **Steps:** from the fake dir (no venv yet): `--install --dryrun --non-interactive`
- [ ] **Expected:** Triton row reads `constraint determined after PyTorch installs`; SA row reads `determined after PyTorch installs`. No concrete Triton version is promised.
- [ ] **Known limitation (pre-existing, tracked for next release):** this dryrun CREATES a venv in the fake dir as a side effect. Delete `venv/` afterwards to reset.

### 2.2 Verifier fence: a deviation prints but does not fail the run

- [ ] This cannot be induced safely by hand on a real environment. Covered by automation: `test_probe_failure_cannot_raise`, `test_install_actually_calls_the_verifier`, and the 12-mutant sweep. **Skip manually** — listed so nobody invents a destructive way to test it.

## What the automated tests DON'T cover

- Real pip resolver behavior against the live PyPI index (probes are emulated in tests; HV.5 sees the real one)
- Console rendering of the verification block on cp437/cp1252 (HV.2)
- The end-to-end timing feel of the extra verification probe (~2s observed)
- CI actually executing on GitHub's windows-latest runners (Section 3)
- Whether upstream ever publishes a 3.6.0.post27 — the first real within-tier upgrade will be the probe fix's true field test
- Same-version churn (uninstall+reinstall at the same version) — the verifier's documented blind spot; no manual step can see it either
